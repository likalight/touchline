# Impact

## The problem

A live football broadcast has a handful of graphics operators, a few seconds of delay, and one
version of the story for every viewer. Analysts want depth, casual fans want the story, blind and
low-vision fans get almost nothing, and a viewer in another market gets graphics in someone else's
language. Data on screen says *what* happened; working out *why it mattered*, live and correctly,
is still done by hand.

At least **2.2 billion people** have a near or distance vision impairment
([WHO, February 2026](https://www.who.int/news-room/fact-sheets/detail/blindness-and-visual-impairment)).
For them, a stats overlay is invisible unless something describes it.

## What changes with Touchline

| For | Before | With Touchline | Evidence |
|---|---|---|---|
| Graphics desk | Operators type and check each graphic | Timed, machine-readable cues keyed to the match clock, server timing reported in EVAL.md, with a CasparCG/SPX template; playout latency remains to be measured | [EVAL.md](EVAL.md), `web/templates/touchline-graphics.html` |
| Editor | Chooses what airs by hand | The Producer agent scores every moment and airs, cuts in, queues or drops it with a stated reason; review mode keeps a human in charge | Producer console, `tests/test_producer_editorial.py` |
| Trust and compliance | A wrong number on air is a correction and a headline | Every number re-derived from the raw events; 735 of 735 insights verified; model copy blocked if any figure or name is unsupported | [EVAL.md](EVAL.md), resilience drills |
| Casual fans | The same graphic as the analyst | Four voices for each moment, their club, their favourite players, one metric, their language | Live app |
| Blind and low-vision fans | Little or nothing | Spoken audio description of where play is, plus two-voice commentary with captions | Audio description mode, Commentary |
| Fans in other markets | Graphics in the broadcaster's language | English, Spanish, French and Portuguese built in; any other language through Microsoft Foundry, re-checked before it airs | `touchline/i18n.py`, `touchline/agents/narrator.py` |
| Social and digital teams | Clip and caption after the match | A personal highlights reel per fan, an edit list for the studio, and a post-match package and social cards generated by an Azure Function at full time | My Match, `functions/` |
| Operations | Hope the feed is clean | Malformed, duplicated and out-of-order events repaired exactly once; agent and model failures recover live | Resilience drills, `tests/test_drills.py` |

## Cost

About **$0.06 per match per extra language** through Azure OpenAI; the four built-in languages
need no model at all. A match's compute fits comfortably in the Container Apps free grant at
demo scale. Details: [BROADCASTERS.md](BROADCASTERS.md#cost-per-match).

## Path to production

| Phase | What happens | Done when |
|---|---|---|
| Week 1–2: shadow | Touchline runs on a real feed through Event Hubs, graphics go to a preview channel only | Verification rate and latency match the evaluation gate on real matches |
| Week 3–6: assisted | Review mode on air: producers approve each graphic | Producers accept most suggestions without editing |
| Week 7+: live | Auto-air for routine graphics; personal modes and audio description in the streaming app | Viewer feedback (the Useful buttons) and accessibility testing meet the agreed bar |

Each broadcaster or region gets its own deployment and Foundry project (`azd env new`), so data,
agents, content policies and costs stay separate. See [GOVERNANCE.md](GOVERNANCE.md).

## Testing with people

Every card in the app has **Useful** and **Not for me** buttons. Votes are counted per persona
and moment type (`GET /api/matches/{id}/feedback`, also in the audit export and the Agents at
work panel), so the impact numbers come from viewers rather than from us. The ten-minute session
we run is in [USER_TEST.md](USER_TEST.md).

## Evidence boundary

The workflows above are intended benefits, not measured adoption or accessibility outcomes.
No completed participant results are recorded in USER_TEST.md. Do not use general population
statistics as the count of users served by this prototype. The recorded local measurements
cover synthetic correctness and server timing; end-to-end graphics delay, actual Azure costs,
producer time saved and user usefulness require the deployment and pilot observations.
